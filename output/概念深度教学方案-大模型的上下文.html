① 诊断报告 —— 学生在哪里"卡"住了？

1.1 存在论诊断（学生把概念当成了什么？）

学生心中的"影子"典型话术真实样貌
影子 A：上下文 = 输入的提示词 "上下文就是我发给它的问题" 还包括系统提示、对话历史、工具返回
影子 B：上下文 = 聊天记录 "它不是一直记着我前面说的话吗？" 模型本身无状态，"记忆"依赖当前对话的上下文窗口
影子 C：上下文越长越好 "给它 200K 上下文，它就什么都懂" 存在"中间遗忘 (Lost in the Middle)" + 推理成本上升
影子 D：上下文 = 记忆 "下次再开新对话它还记得我" 跨会话不持久，需要外接向量库/数据库
教学切入点 先做"截断实验"——给学生一份 50 页文档，问"文档第 23 页第 4 段说了什么"，让 ta 发现模型真的"看见"了这些 token，但中间位置的内容最容易被忽略。

1.2 本质论诊断（学生漏掉了什么内在结构？）

必备要素学生是否意识到
物理层：token 序列、位置编码、注意力掩码❌ 大部分学生以为文本是"整体理解"的
逻辑层：System / User / Assistant / Tool 四种角色消息❌ 只看到自己发的内容
功能层：上下文窗口大小（4K / 32K / 128K / 200K / 2M）⚠️ 知道有上限，但不知道为什么
限制层：位置偏差（首尾效应）、注意力稀释、推理成本❌ 完全没意识到
扩展层：RAG、压缩、摘要、外部记忆❌ 没听过
突破口 用"路灯下找钥匙"的隐喻——模型只能"看见"上下文里的东西，没放进去的内容就像车灯照不到的黑夜。

1.3 概念论诊断（学生能用概念做事吗？）

任务层级学生能做到吗？
识别：看到 ChatGPT 截图能指出"哪些是上下文"⚠️ 容易漏掉系统提示
区分：能说清"上下文 ≠ 记忆 ≠ 输入"❌ 概念混用
解释：能说清"为什么模型聊久了会忘记开头"❌ 不知道位置衰减
设计：能为长文档问答系统设计上下文管理❌ 没方法
评价：能批评"上下文越大越好"的误区❌ 缺乏成本/位置意识

② 教学设计 —— 「普遍性→特殊性→个体性」三环节

2.1 普遍性：什么是"上下文"？（建立统一定义）

定义：大模型的"上下文"是模型在生成下一个 token 时能够"看到"的全部文本范围。
System Prompt（系统提示，定义角色/规则）
← 模型"出厂设置"
User Message（用户输入，本轮问题）
← 学生最熟悉的部分
Assistant Message（助手历史回复）
← 多轮对话累积
Tool Output（工具返回）/ RAG 检索结果
← 外部世界接口
▼
大模型（黑盒）
▼
下一个 token
关键洞见：上下文 = 模型的"全部工作记忆 + 外部世界接口"。它不是数据库，不是硬盘，而是"此刻模型眼前的那张桌子"。

2.2 特殊性：5 类上下文策略（识别差异）

1

静态提示型

固定模板，单轮调用
文本分类、翻译

2

滑动窗口型

固定 N tokens，截断最早
长文档摘要、流日志

3

累积对话型

完整保留对话历史
ChatGPT 多轮对话

4

检索增强型 (RAG)

动态从向量库检索
企业知识库问答

5

压缩摘要型

自动压缩早期内容
长程任务代理

教师提问 "如果你是产品经理，要做一个 10 万行代码的代码评审 AI，你会选哪种？"
答：④ RAG（不可能把全部代码塞进上下文） + ⑤ 压缩摘要（保留关键决策历史）。

2.3 个体性：在真实模型里落地

模型上下文窗口适合任务注意
GPT-4 Turbo128K长文档分析中间位置易丢
GPT-4o128K多模态长对话视频/音频也占窗口
Claude 3.5 Sonnet200K长文档推理性能稳定
Gemini 1.5 Pro2M整本书/视频成本高
DeepSeek-V364K中文长文本中文友好
通义千问 Qwen2.5128K~1M全场景开源可微调
体验任务 让学生分别用 4K 和 128K 窗口问同一份长文档的"中间段落细节"，直观感受"中间遗忘"。

③ 判断与推理 —— 四层递进训练

① 质的判断 问题：下面这段对话，哪些属于"上下文"？ 
System: 你是一位耐心的数学老师
User: 1+1 等于几？
Assistant: 1+1 = 2
User: 那 2+2 呢？
[模型生成的下一个回答]
✅ 答案：全部四行 + 当前正在生成的，都是上下文。
② 反思判断 问题：模型在 A 对话里记住了用户的名字"小明"，关闭对话后重开新对话，模型还记得吗？

✅ 答案：不记得。模型本身无状态（stateless），跨会话记忆需要外接"长期记忆系统"（如向量数据库、键值存储）。

上下文 (Context)记忆 (Memory)输入 (Input)
持久性仅当前会话跨会话（需外存）单次
范围窗口内全部理论无限当前 prompt
类比工作台上的工具仓库里的存货今天寄来的包裹
③ 必然判断 问题：为什么上下文窗口不是越大越好？

三层原因：
  1. 注意力稀释 (Attention Dilution)：上下文越长，每个 token 分到的注意力权重越低 → 中间内容"被忽略"
  2. 位置偏差 (Position Bias)：模型对首尾内容记得清，中间容易丢（Lost in the Middle 现象）
  3. 成本爆炸 (Cost Explosion)：上下文长度 L，推理计算量约 O(L²) → 200K 上下文比 4K 贵几十倍
数据点 Stanford 研究表明，把关键信息放在 32K 上下文的中间位置，模型回答准确率比放在首尾低 30%+。
④ 概念判断（应用设计） 任务：请你为以下场景选择最合适的上下文策略，并说明理由：
  1. 客服机器人：用户问"我昨天买的鞋子几号发货？"
  2. 法律 AI：分析 500 页合同，找出违约条款
  3. 编程助手：用户在 50 轮对话中迭代开发一个 Web 应用
  4. 小说创作：让模型续写《三国演义》第 80 回
参考答案：
  1. RAG + 工具调用：从订单数据库检索实时信息
  2. 滑动窗口 + 检索增强：分块读取，定位关键条款
  3. 压缩摘要：每 10 轮总结一次，保留关键决策
  4. 累积对话 + 风格示例：保留原著前文 + 风格提示

4.3 DeepSeek 辅助 Prompt

学生自查 Prompt： 
我正在学习"大模型的上下文"这个概念。请按以下结构帮我自查：

1. 用一句话定义"上下文"，不超过 30 字
2. 列出上下文的 4 个组成部分
3. 解释为什么"上下文 ≠ 记忆"
4. 说出 3 类上下文策略及其适用场景
5. 设计一个"长文档问答"场景的上下文管理方案

我会给你我的回答，请你打分（0-10）并指出"影子理解"。
教师备课 Prompt： 
我要给学生讲"大模型的上下文"（学段：高中信息技术，1 课时 45 分钟）。

请帮我设计：
1. 一个 5 分钟的导入故事（学生熟悉的场景）
2. 3 个递进式课堂提问（从定义 → 区分 → 应用）
3. 1 个分组任务（4 人小组，30 分钟）
4. 1 道课后思考题（开放性，能区分 A/B 层次）

要求：贴合"黑格尔概念论"——让学生先识别"影子"，再突破，最后能在新场景中应用。

⑤ 核心教学观点

大模型的"上下文"不是聊天记录，不是数据库，不是记忆，而是模型生成下一个 token 时能"看到"的全部文本——它有窗口限制、位置偏差、成本代价，需要根据场景设计"静态/滑动/累积/RAG/压缩"五种策略才能用好。
教学反思：本方案按"识别影子 → 建立定义 → 区分变体 → 应用设计"四步推进，重点突破"上下文 = 输入/记忆"两大混淆。建议第一节课做截断实验，第二节课做策略设计任务。
