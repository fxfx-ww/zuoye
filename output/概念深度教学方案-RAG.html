① 诊断报告 —— 学生在哪里"卡"住了？

1.1 存在论诊断（学生把概念当成了什么？）

学生心中的"影子"典型话术真实样貌
影子 A：RAG = 向量数据库 "RAG 不就是把文档存进向量库吗？" 向量库只是检索侧的一个组件；RAG = 检索 + 增强 + 生成 三段式
影子 B：RAG = 把文档全塞进 prompt "RAG 就是把资料都拼到上下文里呗？" RAG 是按需取用只检索相关片段，不是暴力拼长上下文
影子 C：RAG = 搜索引擎/关键词匹配 "RAG 不就是搜一下关键词吗？" 关键词匹配 ≠ 语义检索（embedding），工程上还要加重排 rerank
影子 D：RAG = 模型微调 "给模型加知识不就得重新训练吗？" 微调改模型参数（行为）；RAG 不改参数（外挂知识、可溯源）；两者互补
教学切入点 先抛出一个反直觉现象——"为什么给模型一份它没训练过的内部文档，它也能答对细节？"
让学生意识到答案不是来自模型"记住"，而是来自"当场翻书"。

1.2 本质论诊断（学生漏掉了什么内在结构？）

必备要素学生是否意识到
检索侧 Retrieval：切分 → 向量化 → 相似度检索 → 重排❌ 只知道"搜索"两个字
增强侧 Augmentation：把检索片段拼进 prompt（提示+片段+问题）❌ 没意识到"拼"的动作就是概念名里的 Augmented
生成侧 Generation：LLM 基于增强后的上下文生成并标注引用⚠️ 知道最终是 LLM 回答
限制层：切分粒度、召回率/准确率、上下文窗口、幻觉控制❌ 没概念
与邻近概念关系：微调 / 长上下文 / 搜索引擎 / Agent❌ 全部混为一谈
突破口 用"开卷考试 vs 闭卷考试"的隐喻——普通 LLM 是闭卷（只靠参数记忆），RAG 是开卷（先查参考资料再作答，还能标"见第 X 页"）。学生瞬间理解"为什么能减少幻觉"。

1.3 概念论诊断（学生能用概念做事吗？）

任务层级学生能做到吗？
识别：看到一张 RAG 架构图能指出 R / A / G 三段⚠️ 常把向量库当全部
区分：能说清 RAG vs 微调 vs 长上下文 的适用边界❌ 混用
解释：能解释"为什么开卷能减少幻觉"❌ 说不清机制
设计：能为企业客服/法律问答设计 RAG 方案❌ 没方法
评价：能评估一个 RAG 系统的检索质量（召回/精度）❌ 没指标意识

② 教学设计 —— 「普遍性→特殊性→个体性」三环节

2.1 普遍性：什么是"RAG"？（建立统一定义）

定义：RAG（Retrieval-Augmented Generation，检索增强生成）是一种让 LLM 先检索外部知识、再基于检索结果生成回答的架构。
用户提问："公司年假政策是怎样的？"
▼
R · Retrieval 检索 外部知识库 → 相关片段
文档切分 chunking → 向量化 embedding → 相似度检索 → 重排 rerank
▼
A · Augmentation 增强 检索片段 → 拼进上下文
[系统提示] 请仅依据资料回答 + [资料1][资料2]… + [用户问题]
▼
G · Generation 生成 LLM 基于增强上下文作答
生成答案 + 标注引用来源（"见《员工手册》第 12 条"）
▼
✅ 带出处、可溯源的准确回答
关键洞见：RAG 的本质 = 把"记忆"从模型参数里搬到外部知识库。模型不再需要"背下"一切，只需要"会查 + 会读 + 会答"。

2.2 特殊性：RAG 的 5 类形态（演化时间线）

① 朴素 RAG (Naive) 最基本形态

切分 → 向量化 → 检索 → 拼接 → 生成

最经典三段式，直接简单，是理解 RAG 的起点。

② 高级 RAG (Advanced) 深化"检索"

朴素 + 查询改写 + 混合检索(BM25+向量) + 重排

解决"问题表述差 / 关键词不匹配"导致的检索质量低。

③ 模块化 RAG (Modular) 扩展"增强"

检索/记忆/路由/融合等模块可插拔

按业务需求自由组装，路由决定走哪个检索通道。

④ Agentic RAG (智能体) 智能化"决策"

Agent 自主决定何时查、查什么、多轮查

Agent 先判断"要不要查资料"，再规划检索策略（衔接 Agent 概念）。

⑤ Graph RAG (图谱) 结构化"组织"

知识图谱组织实体关系，多跳推理

回答"人物关系 / 跨段落关联"类问题（微软提出）。

教师提问 "一个客服机器人，用户问'我上周买的鞋能退吗'，用哪类 RAG 最合适？"
答：④ Agentic RAG——需要 Agent 判断"退换货政策在知识库哪一块"，可能还要先查订单再查政策（多跳）。

2.3 个体性：真实场景落地 + 与已学概念统一

四个概念在同一个企业 HR 助手案例中闭环：

🤖 Agent
执行问答流程的主体
＋
🧩 Skill
封装"知识库问答"能力
＋
👁️ 上下文
Augmentation 注入检索结果
＝
📚 RAG
先查资料再回答的机制
已学概念在本案例中的角色
Agent（主体）执行整个问答流程的智能体
Skill（能力包）"知识库问答"可封装为数据查询类 Skill（如 westock-data）

③ 判断与推理 —— 四层递进训练

① 质的判断 问题：以下 RAG 流程中，标注的 R / A / G 分别指什么？ 
用户提问 → [①把文档切成块并向量化存储] → [②检索相似片段]
→ [③把片段拼进 prompt] → [④LLM 基于上下文生成回答]
✅ 答案：①+② 是 R（Retrieval 检索）；③ 是 A（Augmentation 增强）；④ 是 G（Generation 生成）。向量化存储属于检索侧的准备，不是独立的"第四段"。
② 反思判断 问题：请区分 RAG 与微调 / 长上下文 / 搜索引擎。
维度RAG微调 Fine-tuning长上下文窗口搜索引擎
是否改模型参数否（外挂知识）是（更新权重）否否（无 LLM）
知识更新秒级（换库即可）天~周级（重训）—爬虫级
能否溯源✅ 可标引用来源❌ 黑盒⚠️ 依赖模型记忆✅ 给链接
幻觉控制强（开卷作答）中（仍可能编造）弱（中间易忘）无生成
成本检索 + 少量 token训练算力长 token 贵索引维护
适用动态知识/需溯源/内部文档特定风格/格式/行为单次长文档理解公开网页检索
类比开卷带参考书考前刷题改变习惯考卷印得特别长图书馆查目录
关键洞见：
  • RAG vs 微调：RAG 解决"知道什么"（知识），微调解决"怎么回答"（风格行为）——不是二选一，常组合用
  • RAG vs 长上下文：长窗口是"把书全印在考卷上"（贵且中间易忘）；RAG 是"按需翻到相关页"（省且准）——200K 窗口时代 RAG 依然必要
  • RAG ⊃ 检索：搜索引擎只到 R 为止，RAG 多了 A+G（增强+生成）
③ 必然判断 问题：为什么"多了一个检索步骤"就能减少幻觉？

三层必然性：
  1. 信息来源改变：闭卷时模型只能从参数里"回忆"，记不清就编（幻觉根源）；开卷后答案"有据可依"。
  2. 约束生成空间：增强后的 prompt 明确"请仅依据资料回答"，把发挥空间从"全部参数记忆"压缩到"给定资料"。
  3. 可验证性：回答标注"见《员工手册》第 12 条"——错误可被追溯到来源，系统才能被人工审核与修正。
💡 数据点 多项评测显示，在知识密集型问答（医疗、法律）中，RAG 相比纯 LLM 回答准确率可提升 20-40%，显著降低"一本正经胡说八道"的比例。
④ 概念判断（应用设计） 任务：为以下四个业务场景选择方案，并说明理由。
场景推荐方案理由
1. HR 助手：回答《员工手册》问题RAG知识更新频繁，需溯源
2. 法律 AI：分析 500 页合同找违约条款RAG + 长上下文文档长且需精确引用条款
3. 小说续写：模仿某作家文风微调核心是"文风行为"而非知识
4. 医院导诊：根据症状推荐科室微调 + RAG 混合术语库 RAG + 分诊行为微调
💡 决策口诀 知识问题 → RAG；行为风格问题 → 微调；文档超长 → 加长窗口；三者都不够 → 组合。

4.3 DeepSeek 辅助 Prompt

学生自查 Prompt： 
我正在学习"RAG（检索增强生成）"这个概念。请按以下结构帮我自查：

1. 用一句话定义 RAG，不超过 30 字
2. 标出 R/A/G 三段式，并各举一个组件
3. 用对照表区分 RAG / 微调 / 长上下文
4. 解释"为什么开卷考试（RAG）能减少幻觉"
5. 为企业客服设计一个最小 RAG 方案（画出 5 步流程）

我会给你我的回答，请你打分（0-10）并指出"影子理解"。
教师备课 Prompt： 
我要给学生讲"RAG（检索增强生成）"（学段：大学 AI 导论，1 课时 45 分钟）。

请帮我设计：
1. 一个 5 分钟的导入故事（用"开卷考试"或"图书馆找书"的隐喻）
2. 3 个递进式课堂提问（从定义 → 区分 → 设计）
3. 1 个分组任务（4 人小组，30 分钟）：为一个场景设计 RAG 架构图
4. 1 道课后思考题（开放性：RAG 会被长上下文窗口取代吗？）

要求：贴合"黑格尔概念论"——让学生先识别"影子"（特别是把 RAG 当成向量库的误区），再突破，最后能独立设计。

⑤ 核心教学观点

RAG 不是向量数据库，不是搜索引擎，也不是微调——它是把 LLM 从"闭卷考试"变成"开卷考试"的架构：先检索（Retrieval）外部知识、再增强（Augmentation）进上下文、最后生成（Generation）带出处的回答。它不改变模型参数，只改变模型的"信息来源"。
教学反思：本方案是四个概念（Agent→Skill→上下文→RAG）学习闭环的收官。最大误区是"RAG = 向量库"——要用架构图反复强调 R/A/G 三段式。建议用"开卷考试"隐喻做导入，用一个企业知识库案例贯穿始终，最后用"RAG 会被长上下文取代吗"的开放题收尾，引导学生看到 200K 窗口时代 RAG 依然不可替代（成本 + 溯源 + 更新速度）。
